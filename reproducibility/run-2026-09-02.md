What changed between the two runs is the pipeline, not the model: the first run analysed
and patched one increment at a time (38 calls); the current one gives the model a bounded
workspace to build the planned increments in, verifies the whole product afterwards in the
browser and against the request's business rules, and sends only what failed back as a
scoped fix. The current run also checks every business rule independently of the model's
own tests, which the first run did not.
