Build a production-ready, clean task manager web app called "Tally" for a small team. Stack: React + TypeScript (Vite), react-router-dom, React context + reducer for shared state, plain CSS with design tokens (no CSS framework), Vitest for unit tests, no external network requests, mock data only. Routes: "/" (today view: tasks due today and overdue, counts by status), "/tasks" (all tasks with search, filter by status and assignee, sort by due date or priority; state in the URL), "/tasks/:id" (task detail with edit form and activity log), "/board" (kanban by status with drag-free move buttons), "/settings" (theme toggle, default assignee). Rules that must be pure functions with unit tests: 1. A task is OVERDUE when its due date is before today and its status is not done. 2. Priority score = base priority (low 1, medium 2, high 3) times 2 if overdue, plus 1 if it has more than 3 subtasks; ties sort by due date ascending. 3. Moving a task to done sets completedAt and clears the overdue flag; moving it back clears completedAt. 4. Recurring tasks: when a task with a repeat interval (daily, weekly, monthly) is marked done, a new task is created with the next due date computed from the ORIGINAL due date, not from today; months clamp to the last valid day. 5. Search matches title and tags, case-insensitive, and the filters combine with AND. Persist all changes to localStorage. Dark-first theme, keyboard-reachable controls, a 12-task seeded data set with at least 3 overdue and 2 recurring tasks.
